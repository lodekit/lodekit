# Dev Flow v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Vendor the agent dev process into the repo (skills, hooks, config), adopt beads as the single memory/task/deferral substrate, and ship the `pair|auto × spec|task` session model — per `docs/specs/2026-07-15-dev-flow-v2-design.md`.

**Architecture:** Four sequential PRs (spec §11), each leaving the repo working: (1) config decoupling, (2) beads adoption, (3) vendored skills + hooks, (4) ponytail + Pocock + Codex. Canonical prose lives in `.agents/`; Claude Code reads it via committed `.claude/` symlinks; Codex reads it natively.

**Tech Stack:** plain markdown skills (Agent Skills standard), `bd` (beads) 1.1.0, codebase-memory-mcp ≥ 0.8.1, Node ≥ 18 for `setup.mjs`, `gh` CLI.

## Global Constraints

- Spec: `docs/specs/2026-07-15-dev-flow-v2-design.md` — decision record D1–D12 governs; on conflict, the spec wins.
- **Each phase is its own branch + PR; the person merges.** Branch off latest `master` after the previous phase merges. Never merge unattended. PR titles below are load-bearing (squash-merge subjects).
- Conventional PR shape: Summary / Notes / Test plan body.
- No `Co-Authored-By` trailers.
- macOS case-insensitive FS assumed (spec non-goal: Linux).
- `docs/changelog.md`: **no entries** — this is internal work, invisible to Lodekit users.
- Every vendored-file modification must be listed in `.agents/UPSTREAM.md` (created in Phase 3; Phases 1–2 create no vendored files).
- Skill invocation names are bare (e.g. `brainstorming`), never plugin-namespaced.
- The executing agent runs under the *current* process (superpowers plugin) until Phase 3 lands; do not disable the plugin before Phase 3's switch step.

- [ ] **Step 1: Write `SKILL.md`** (exact content):

```markdown
---
name: drain-deferrals
description: Drain deferred work from beads into GitHub issues. Use when the engineer asks to drain, triage, or review deferrals, or mentions the defer backlog. Pair-mode only — iterates with the engineer; never runs unattended.
---

# Drain deferrals

Deferrals are beads labeled `defer` (severity/confidence stamped, provenance in the
body). This skill moves them — deliberately, with the engineer — into GitHub issues,
which are the only durable human backlog.

**Guard:** requires the engineer present. In an auto session, stop: "drain-deferrals
is pair-only — re-run in a pair session."

1. **Sync:** `bd dolt pull`; if it brought changes, `bd recompute-blocked`.
2. **Gather:** `bd list --label defer --status open --json`.
3. **Consolidate:** group related beads; check `bd duplicates`; propose merges and
   rewordings. Present a digest — counts, groups, one line per bead.
4. **Iterate:** per group, draft the issue (title, body with provenance links, labels)
   and confirm with the engineer. Park or close-as-wontfix on their call.
5. **File:** `gh issue create` per approved draft, then set backlog fields per
   `references/github-backlog.md` (project item + type / Area / Priority / Definition).
6. **Close drained beads:** `bd close <id> --reason "drained to <issue-url>"`.
7. **Push:** `bd dolt push`. Report: N drained, M parked, issue links.
```

- [ ] **Step 1: Write `SKILL.md`** (exact content):

```markdown
---
name: session
description: Establish the session's operating mode — pair or auto (who approves) × spec or task (how much ceremony). Use at session start, when invoked as /session [pair|auto] [spec|task], or whenever the operating mode is unclear.
---

# session — operating mode

Resolve the mode, announce it ("Session mode: pair task"), then follow its contract
for the rest of the session.

## Resolving the mode

- **Axis 1 (who approves):** `pair` unless `auto` was explicitly given. Never infer
  auto.
- **Axis 2 (ceremony):** if not given, infer from the request — new feature, new
  component, large refactor, unclear scope → `spec`; small fix, minor change, minor
  refactor → `task`. In pair, confirm the inference before proceeding; in auto, state
  it and proceed.

## Triage before ceremony

| Request | Route |
|---|---|
| Quick question ("what does X do?", "explain this error") | Answer. No bead, no skill. |
| Simple change — ONLY: typo, comment, rename, or a single-file obvious fix with an obvious check | Do it, verify with evidence, commit. Bead optional. Anything that doesn't fit this list is not simple. |
| Research query ("how does X work?", "compare A vs B") | research-driven-development. |
| Everything else | The mode contract below. |

## pair

Skills run unmodified: interactive brainstorming, partner approval at every gate,
questions block until answered. Ask rather than assume.

## auto

The engineer is absent; you decide. Never raise a question. Invest more before
deciding: gather context, research, adversarially verify your own conclusions — you
are the only reviewer present. Gates are substituted, never deleted:

| Gate | pair | auto |
|---|---|---|
| Unknowns before design | ask the engineer | research-driven-development, verified findings |
| Spec approval | engineer approves | stress-test interrogation; revise until it passes |
| Plan approval | engineer approves | stress-test interrogation |
| Code review | engineer + subagent gates | full 4-gate subagent review; reject and re-delegate on failure |

**STOP conditions apply verbatim** (blocker; critical plan gap; instruction you don't
understand; verification fails repeatedly). In auto, "stop and ask for help" means:

1. File the blocker as a bead labeled `human` (severity/confidence stamp).
2. Write a handoff (session-handoff).
3. `bd remember "continuation-<date>-<topic>: <state>"`, then `bd dolt push`.
4. End with a final message stating exactly where and why you stopped.

Never guess past a blocker. Resume is session-independent: the next session's
getting-up-to-speed surfaces the continuation memory, the handoff, and
`bd list --label human`.

## spec

`docs/plans/` + epic/task beads → execution. Use codebase-design vocabulary when a
```

```js
#!/usr/bin/env node
// Lodekit agent-tooling bootstrap + doctor. Idempotent; safe to re-run.
// Wires what Codex cannot read from the repo, and verifies both harnesses.
import { execFileSync } from 'node:child_process';
import { existsSync, readFileSync, appendFileSync, readdirSync, readlinkSync, mkdirSync } from 'node:fs';
import { homedir } from 'node:os';
import { join, dirname, resolve } from 'node:path';
import { fileURLToPath } from 'node:url';

const repo = resolve(dirname(fileURLToPath(import.meta.url)), '..', '..');
const results = [];
const ok = (name, detail = '') => results.push({ name, pass: true, detail });
const fail = (name, detail) => results.push({ name, pass: false, detail });
const run = (cmd, args) => execFileSync(cmd, args, { encoding: 'utf8' }).trim();

// 1. binaries
let bdPresent = false;
try {
  const v = run('bd', ['version']);
  const m = v.match(/(\d+)\.(\d+)\.\d+/);
  bdPresent = true;
  if (m && (+m[1] > 1 || (+m[1] === 1 && +m[2] >= 1))) ok('bd >= 1.1.0', v);
  else fail('bd >= 1.1.0', `${v} — brew upgrade beads`);
} catch {
  fail('bd >= 1.1.0', 'not found — brew install beads');
}
try {
  ok('codebase-memory-mcp', run('codebase-memory-mcp', ['--version']));
} catch {
  fail('codebase-memory-mcp', 'not found — see AGENTS.md (brew tap DeusData)');
}

// 2. repo wiring
try {
  const t = readlinkSync(join(repo, 'CLAUDE.md'));
  t === 'AGENTS.md' ? ok('CLAUDE.md -> AGENTS.md') : fail('CLAUDE.md symlink', `points at ${t}`);
} catch {
  fail('CLAUDE.md symlink', 'missing or not a symlink');
}
try {
  const canonical = readdirSync(join(repo, '.agents', 'skills'));
  const links = readdirSync(join(repo, '.claude', 'skills'));
  const missing = canonical.filter((s) => !links.includes(s));
  const broken = links.filter((l) => !existsSync(join(repo, '.claude', 'skills', l)));
  if (!missing.length && !broken.length) ok(`skill symlinks (${links.length})`);
  else fail('skill symlinks', `missing: ${missing.join(',') || '-'}; broken: ${broken.join(',') || '-'}`);
} catch (e) {
  fail('skill symlinks', String(e));
}

// 3. codex (user-global — the parts Codex cannot read from the repo)
const codexConfig = join(homedir(), '.codex', 'config.toml');
const marker = '[mcp_servers.codebase-memory-mcp]';
try {
  mkdirSync(dirname(codexConfig), { recursive: true });
  const current = existsSync(codexConfig) ? readFileSync(codexConfig, 'utf8') : '';
  if (current.includes(marker)) ok('codex mcp config', 'already present');
  else {
    appendFileSync(codexConfig, `\n# added by lodekit .agents/scripts/setup.mjs\n${marker}\ncommand = "codebase-memory-mcp"\nargs = []\n`);
    ok('codex mcp config', `appended to ${codexConfig}`);
  }
} catch (e) {
  fail('codex mcp config', String(e));
}
if (bdPresent) {
  try {
    run('bd', ['setup', 'codex']);
    ok('bd codex hooks');
  } catch {
    fail('bd codex hooks', 'bd setup codex failed — run it manually');
  }
}

// report
let failed = 0;
for (const r of results) {
  console.log(`${r.pass ? 'ok  ' : 'FAIL'}  ${r.name}${r.detail ? ` — ${r.detail}` : ''}`);
  if (!r.pass) failed++;
}
console.log(failed ? `\n${failed} check(s) failed` : '\nall checks passed');
process.exit(failed ? 1 : 0);
```
