# Electron 43 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Each Task becomes a bead (`bd create -t task --parent <epic-id>`). Steps within tasks use checkbox (`- [ ]`) syntax for human readability.

**Goal:** Move the manager off Electron 33.4.11 to current Electron 43.x, clearing the ~19 `pnpm audit` advisories attributed to it (GitHub issue #164).

**Architecture:** The manager is a main-process-only Electron app (`app`, `Tray`, `Menu`, `nativeImage`, `shell` — no BrowserWindow, no renderer, no preload). The engine runs as a direct child Node process on the bundled Node 24.12.0, so Electron's ABI and bundled Node are irrelevant to it. Electron's documented breaking changes for 34→43 touch **none** of the APIs the manager uses; the only product-relevant change is the runtime floor — Electron 38+ requires macOS 12 (Monterey).

**Tech Stack:** Electron ^43.2.0 (from ^33.2.0), electron-builder 26.15.3 (unchanged — current major), vitest (unchanged).

## Global Constraints

- `manager` stays zero prod dependencies; Electron remains a **devDependency** (it ships via electron-builder's own bundling, not `node_modules`).
- The pinned Lodekit-local Node stays **24.12.0** (`prepare-bundle.mjs`) — issue #164 confirms it is independent of Electron here.
- `electron-builder.yml` semantics unchanged: ad-hoc identity `"-"`, `LSUIElement: true`, zip target, no asar, `afterPack: assert-pack.cjs`.
- `pnpm --filter @lodekit/manager make` must be run on Node v24.12.0 (`prepare-bundle.mjs` hard-asserts; the local machine is already on it).
- Work lands on this worktree's `engine` branch (already fast-forwarded to master); PR from it, squash-merge, conventional title.

## Known limitation (surfaced, not silent)

The issue's done-when says `make` produces a launching `Lodekit.app` on **both architectures**. Locally we can only build/launch darwin-arm64 — a cross-target bundle fails `assertNativeModule` by design, and the release workflow (the only x64 builder, `macos-15-intel`) fires solely on merged release PRs. Nothing in this change is arch-specific (electron-builder downloads Electron's official per-arch dist zips), so the plan verifies arm64 locally and leaves x64 to the next release build. If you want pre-release x64 proof, the alternative is a temporary `workflow_dispatch` build job — decide at plan review.

### Task 2: Package and launch verification (darwin-arm64)

**Files:**
- None modified — this task produces verification evidence only. Build outputs land in `manager/build/` and `manager/dist/` (gitignored).

**Interfaces:**
- Consumes: `node_modules/electron` at 43.x from Task 1.
- Produces: evidence for Task 3's PR test plan — dev-mode boot log lines, `make` success, packaged-app health check, clean quit.

**Acceptance Criteria:**
- `pnpm --filter @lodekit/manager start` boots the tray app on Electron 43 in dev mode (supervisor reaches `running`).
- `pnpm --filter @lodekit/manager make` completes: bundle asserts pass, electron-builder packages and ad-hoc signs, `assert-pack.cjs` afterPack passes (Electron 43's LICENSE + LICENSES.chromium.html collected).
- The packaged `manager/dist/mac-arm64/Lodekit.app` launches: engine health endpoint returns 200, quit leaves no orphan engine process.

- [ ] **Step 1: Confirm port 7777 is free (both dev and packaged runs need it)**

```bash
lsof -nP -iTCP:7777 -sTCP:LISTEN || echo "port free"
```

Expected: `port free`. If a dev engine is running, stop it first — otherwise the manager will surface a port-in-use error instead of `running`.

- [ ] **Step 2: Dev-mode boot check on Electron 43**

```bash
pnpm --filter @lodekit/manager start &
sleep 45
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:7777/api/apps
tail -3 "$HOME"/Library/Logs/Lodekit/manager-*.log | cat
kill %1
```

Expected: curl prints `200`; the manager log shows `state: starting` then `state: running`. (Dev mode runs the workspace engine against `root/` on system Node — the Electron part under test is app boot, Tray, and supervisor wiring.)

- [ ] **Step 3: Build the package**

```bash
pnpm --filter @lodekit/manager make
```

Expected: `Bundle inputs ready: …` (Node v24.12.0 + platform payload), then electron-builder packages with `identity: "-"`; exits 0. `manager/dist/` contains `Lodekit-darwin-arm64-0.1.0.zip` and `mac-arm64/Lodekit.app`. If `assert-pack.cjs` throws, the Electron 43 dist layout changed — stop and investigate, do not patch around it.

- [ ] **Step 4: Verify the packaged app's Electron version and signature**

```bash
# Electron 43's framework plist carries only CFBundleVersion (CFBundleShortVersionString was dropped)
grep -A1 '>CFBundleVersion<' manager/dist/mac-arm64/Lodekit.app/Contents/Frameworks/Electron\ Framework.framework/Resources/Info.plist | tail -1
codesign -dv manager/dist/mac-arm64/Lodekit.app 2>&1 | grep -E "Signature|adhoc"
ls manager/dist/mac-arm64/Lodekit.app/Contents/Resources/LICENSE.electron manager/dist/mac-arm64/Lodekit.app/Contents/Resources/LICENSES.chromium.html
```

Expected: framework version string `43.2.x`; `Signature=adhoc`; both license files present.

- [ ] **Step 5: Launch the packaged app and verify health**

Note: launching uses the real `~/Documents/Lodekit` (created + showcase apps installed only if absent — never clobbers an existing root) and writes to `~/Library/Logs/Lodekit`.

```bash
open manager/dist/mac-arm64/Lodekit.app
sleep 60
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:7777/api/apps
tail -3 "$HOME"/Library/Logs/Lodekit/manager-*.log | cat
```

Expected: `200`; log shows `mode: default` and `state: running`.

- [ ] **Step 6: Clean quit — no orphan engine**

```bash
osascript -e 'quit app "Lodekit"'
sleep 5
pgrep -f "Resources/platform/engine" || echo "no orphan"
```

Expected: `no orphan`.

- [ ] **Step 7: Eyeball the tray (human check, optional but recommended)**

The person confirms: "⬡" glyph visible in the menu bar during Step 5, menu opens, states read correctly. (Full release-level checklist stays `manager/smoke.md` — out of scope for this bump.)
