# TanStack Start Host — Design

**Date:** 2026-07-03
**Status:** Draft, pending review
**Role:** Slice-spec for the app-server-code substrate + HTTP trigger (umbrella spec §2.12),
inserted after the stack-refresh slice and before slice 3 (MCP + skill v0.1) in the
derivation order (`docs/specs/2026-07-02-product-overview-design.md`, §4.2). It resolves
§2.12's substrate obligations by making Lodekit a **TanStack Start host**: apps (and the
dashboard) are TanStack Start applications, built by the runtime and executed in per-app
worker threads inside the one shared process. This slice belongs to v0.1.

Two proofs of concept ground the design (2026-07-03, session scratchpad): (1) TanStack's
standalone server-function compiler runs on a plain two-environment Vite build with a
custom RPC runtime; (2) two Start apps built with `router.basepath` + Vite `base` +
`serverFns.base` under `/<app-id>/` mount as pure fetch handlers in one Node process, SSR
and per-app assets verified. Option (2) — Start wholesale — was chosen.

## 1. The reframe

The app contract stops being an SPA shape Lodekit defines and becomes **a TanStack Start
app, hosted**. The coupling is deliberate and is the positioning: *cloud batteries +
zero-ops hosting for the stack agents already know — powered by TanStack, shadcn, and
SQLite.* Start's concepts — file-based routes, loaders, server functions, SSR — are
Lodekit's app-facing concepts; when Start moves, Lodekit moves. Start's relative
immaturity is accepted, recorded here, and not hedged against with abstraction layers.

What stays Lodekit's: the runtime, the service catalog, the SDK, per-app data scoping,
the dashboard as product surface, the build-for-you model, and the cohesion invariants.
The runtime's headless plumbing (scoped API, SSE) **stays Hono + hc** — "one ecosystem"
is a statement about what agents write, not about the host's internals.

### 1.1 Invariants, revisited deliberately

- **1 — One shared instance: holds.** A built Start app's server output is a pure fetch
  handler (no port, no process). N apps mount in the one runtime; app server code runs in
  per-app **worker threads** inside it — fault containment, never a per-app server.
- **2 — The person never builds: holds.** The runtime drives Start's Vite build
  programmatically, as it drives Vite today.
- **3 — The backup tree is sacred: holds, one amendment.** `routeTree.gen.ts` (Start's
  generated route tree) lives in app source, per Start convention — the apps tree gains
  its first generated-but-committed file. Still human-readable, still dependency-free.
- **4 — HTTP is the runtime's only door: holds, and §2.12's open question closes.**
  Server-side app code reaches services through the SDK **over HTTP loopback** — same
  door, same guardrails. The runtime-injected scoped binding alternative is rejected.
- **5 — The SDK is the only app-facing surface: holds on both sides.** `import { kv }
  from "@lodekit/sdk"` works identically in components, loaders, and server functions.
- **8 — Failures surface, never crash: strengthened.** A crashing or hung server module
  is a worker death → app server-error state → respawn. The runtime never goes down
  with it.

### 1.2 Supersessions

- Stack-refresh (2026-07-03) **app-side** serving rules: the SPA fallback (§5.1) and
  `index.html`-entry contract are deleted — Start owns app routing and the document.
  Stack-refresh's runtime-side content (Hono migration, hc SDK transport, rename) is
  untouched.
- The deferred **slice 4** (multi-page app contract) dissolves — file-based routing
  arrives with Start.
- The discarded umbrella amendment (`801e205`) is re-landed in reworked form (§9).

## 2. App contract v2 (hard cutover)

```
apps/habit-tracker/
  manifest.json            # unchanged: appId, name, description, icon
  routeTree.gen.ts         # generated by the build, committed with the source
  src/
    router.tsx             # getRouter() — Start convention
    routes/
      __root.tsx           # document shell: @lodekit/ui theme + Tailwind css + theme-flash snippet
      index.tsx            # createFileRoute: loader + component
      ...
    styles.css
    ...                    # lib/, components/ — agent's choice
```

- **No `index.html`.** The root route renders the document; HTML comes from SSR
  (canonical Start — no SPA mode, no mode caveats in the skill).
- **Server functions** are Start's `createServerFn`, authored anywhere in `src/`
  (route files or extracted modules); the compiler splits them out of the client bundle.
  Lodekit's one layered rule: **inputs at the trust boundary get a validator**
  (`.inputValidator(zodSchema)`), taught by the skill and emitted by the scaffold.
- **The Vite config is Lodekit's, not the app's** — generated per app by the pipeline:
  `tanstackStart({ router: { basepath: "/<app-id>" }, serverFns: { base:
  "/<app-id>/_serverFn" } })`, Vite `base: "/<app-id>/_build/"`, React + Tailwind
  plugins, shared-install aliases (`react`, `react-dom`, `@lodekit/sdk`, `@lodekit/ui`,
  `@tanstack/*`, `lucide-react`), and the `__LODEKIT_APP_ID__` define in **both**
  environments. Apps carry zero dependencies and zero config.
- **Hard cutover.** Both examples migrate (habit-tracker multi-route, expense-tracker
  single-route); the old SPA contract, its scaffold output, and its serving rules are
  deleted. Pre-0.1, existing personal apps migrate by agent; no dual contract, no
  back-compat reads.
- **Scaffold v2** emits the starter above with one working loader and one validated
  server function, so every new app demonstrates the canonical patterns.

## 3. Build pipeline v2

- Per app, the runtime runs Start's full build programmatically — client + SSR
  environments via the Vite JS API (`createBuilder(...).buildApp()`, the API equivalent
  of the CLI path the PoC proved). **Plan task #1 verifies Start's plugin under the JS
  API**; fallback if it resists: drive `vite build` in a child process with a generated
  config file (accepted, uglier, same contract).
- Output: `cache/<app-id>/client/` (static assets) and `cache/<app-id>/server/server.js`
  (the fetch handler).
- The server bundle is **self-contained** (`noExternal`: react-dom/server, seroval, h3
  bundled in — all pure JS; services are reached over HTTP, so no native deps). The
  cache stays a complete, disposable artifact and workers need no module-resolution
  environment. Fallback if a dependency resists bundling: one cache-level `node_modules`
  symlink into the runtime's install.
- **Vite 6 → 8 workspace-wide** (Start requires it), `@tanstack/react-start` +
  `@tanstack/react-router` current stable; React 19 / Tailwind 4 / zod 4 already in
  place. Pins fixed at implementation.
- Build states (`building → ready | error`), per-app build serialization, SSE broadcast:
  exact current semantics.

## 4. App workers

- On `ready`, the runtime spawns one `worker_threads.Worker` per app that imports the
  app's server bundle. **Rebuild = terminate + respawn** — clean module state on every
  change (no stale modules, no leaked timers).
- Request forwarding: the host posts `{ method, url, headers }` plus a transferred
  request-body stream to the worker; the worker runs `handler.fetch(request)` and posts
  back `{ status, headers }` plus a transferred response-body stream (web streams are
  transferable in Node — SSR streaming survives the boundary).
- A per-request timeout (30s) turns a hung render into a surfaced error response, never
  a hung runtime. Worker crash → app enters server-error state → auto-respawn with
  backoff. Worker env: `LODEKIT_BASE_URL=http://127.0.0.1:<port>` (§6).

## 5. Serving (appHost v2) and health

For `/<app-id>/…`:

- `/<app-id>/_build/*` → static from `cache/<app-id>/client` (existing serveStatic
  machinery; URI-decode 400s and path-containment 403s carry over).
- Everything else, **any method** — pages, `/_serverFn/*` — forwards to the app worker.
- Precedence kept: building page while building, error page on build error; new: an
  explanatory error page when the app is ready but its worker is down. The
  `/<app-id>` → `/<app-id>/` 301 stays. The SPA fallback and `index.html` rules are
  deleted.

**Health:** apps gain a second live dimension next to build state — **server state**
(`starting | running | error(message)`), broadcast on the existing SSE channels and
rendered in the dashboard. Invariant 8 end to end: build failure → build-error page;
render/function failure → error response + server state; worker death → respawn +
visible state; the runtime unaffected in all three.

**Server-function guard (webhooks blocked):** the host rejects `/<app-id>/_serverFn/*`
requests that don't carry same-origin browser fetch markers (`Sec-Fetch-Site:
same-origin`) — Start's own client calls pass; curl and external callers don't. This is
explicitly a **soft** guard on localhost; its job is to make "webhooks are unsupported"
a stated fact until the security body of work designs the real story. Page navigations
are untouched. Webhooks are recorded in the roadmap as a future trigger slice on this
substrate.

## 6. SDK on both sides

- Client side: unchanged (relative URLs against the page origin; hc transport).
- Server side (in a worker): the SDK detects the non-browser context
  (`typeof window === "undefined"`) and targets loopback — base URL from
  `LODEKIT_BASE_URL`, app id from the `__LODEKIT_APP_ID__` define baked into both
  bundles. Same HTTP door, same per-app scoping.
- **`kv.watch` is client-only this slice** (EventSource-based). A server-side
  subscription story belongs to the Tasks/signals design; nothing here forecloses it.
  The skill documents the boundary.

## 7. Dashboard = Start app #0

The dashboard moves onto the same substrate: same pipeline, same worker hosting, special
mount at `/_dashboard` (outside the app-id grammar and the registry; source stays in
`packages/runtime`; not person-deletable). One build shape and one hosting path in the
codebase — and the dashboard becomes the substrate's permanent dogfood: SSR, loaders,
worker forwarding, and `@lodekit/ui`-under-SSR are exercised on every boot.

- **Debug floor:** the dependency-free plain-HTML fallback page in `server.ts` remains
  and covers "dashboard building / build failed / worker down" — the debug surface never
  depends on the substrate being debugged. The manager shows runtime health from outside.
- Boot cost rises (Start build ~2–5s vs ~1s); acceptable for a supervised process that
  boots once. The existing roadmap item (freshness-skip of the dashboard build) is the
  designated fix if it matters.
- Future privilege separation falls out naturally: when the security work gives the
  dashboard powers apps must never have (secrets UI), the dashboard worker carries a
  privileged token in its env; app workers don't. Not built now; recorded so it isn't
  designed away.

## 8. Naming (context.md amendments)

- **Server function** — app-defined code that runs on the server side of the contract,
  in TanStack Start's sense and API (`createServerFn`). Canonical for the §2.12 concept.
  _Avoid:_ server code, RPC, action, endpoint.
- **App worker** — the per-app worker thread hosting an app's server bundle.
  _Avoid:_ sandbox, per-app server, process.
- **Stack** entry rewritten: TanStack Start (React, file-based routes, loaders, server
  functions, SSR) + TypeScript + Tailwind + `@lodekit/ui` + the SDK, on the shared
  toolchain. Apps are **server-rendered**.
- **App contract** entry updated to the §2 shape (manifest + `src/routes` + committed
  `routeTree.gen.ts`; no HTML entry).
- Positioning line available to marketing/docs: *"powered by TanStack, shadcn, and
  SQLite."*

## 9. Umbrella spec & roadmap amendments

Umbrella (`2026-07-02-product-overview-design.md`) — this re-lands the discarded
`801e205` amendment, reworked:

- **§2.5 Stack & app contract** rewritten around Start (§2 here).
- **§2.12** rewritten: the substrate is *Start hosting* (this spec); triggers arrive as
  slices on it — **HTTP** (this slice: server functions + server-rendered routes),
  **Tasks** (task-queue/task-schedule) later, invoking exported functions in the same
  app worker. Sequencing consumers unchanged: secret-store's app door (server functions
  read secrets; values never reach browser code) and integrations (server functions do
  outbound fetch; conveniences later).
- **§2.1 boundary** note: app server code runs inside the runtime (in app workers),
  never as a per-app server.
- **Invariants 1/3/4/5/8** annotated per §1.1.
- **§4.1/§4.2**: this slice enters the v0.1 line between stack-refresh and slice 3
  (MCP + skill); old slice 4 dissolved.
- Dashboard component entry (§2.8): a Start app on the shared substrate.

Roadmap:

- Close "Next design target: app server code" (this spec).
- Secret-store bullet: unblocked by this substrate (app door = SDK from server
  functions); still parked for its own slice.
- Add: **webhooks trigger slice** (reachability, auth, signature guidance — replaces the
  soft guard), **server-side `watch`/signals** (with Tasks), note the dashboard
  freshness-skip item's raised relevance.
- Internal-scheduler note: unchanged (decision still lands with the Tasks slice).
- Claude Design mirror support: dropped (no re-sync obligation for `@lodekit/ui`).

MCP: no tool redesign (slice 3); only mechanical fallout if any (app id and scoped API
are unchanged by this slice).

## 10. Skill obligations (input to slice 3)

The skill teaches the v2 contract by *pointing at* Start knowledge agents already have,
plus Lodekit's deltas: scaffold via MCP (never by hand), the SDK for all data on both
sides, validators mandatory on server-function inputs, `@lodekit/ui` for all UI, never
run builds or dev servers, `kv.watch` client-only, webhooks unsupported.

## 11. Testing

Existing suites (api, kv-api, kv-store, sse, scaffold, registry, mcp integration) stay
green — they test the Hono runtime, which this slice doesn't touch. appHost/e2e suites
are rewritten to the new serving rules. New coverage:

- Pipeline builds a fixture Start app via the JS API (the plan-task-#1 proof, kept as a
  regression test).
- SSR GET of `/<app-id>/` returns rendered HTML (loader content present).
- Server-function POST round-trips through the guard; the same call without same-origin
  markers is rejected.
- Crash containment: a server function that kills its worker → error surfaced, worker
  respawns, runtime and sibling apps unaffected.
- Assets serve under `/<app-id>/_build/*`; building/error/worker-down precedence.
- Dashboard boots as Start app #0 (fallback page during build; served after).
- `@lodekit/ui` SSR smoke: a fixture route importing the component set renders
  server-side without error.
- Workspace `tsc` remains the type-level contract test.

Slice ends with a manual browser smoke of both migrated examples and the dashboard.

## 12. Risks

| Risk | Position |
| --- | --- |
| Start plugin under the Vite JS API | Plan task #1; fallback: child-process `vite build` with generated config |
| Start version churn | Accepted — coupling is the design; pins move deliberately |
| `noExternal` server bundle resists | Fallback: cache-level `node_modules` symlink into the runtime's install |
| Tailwind/react plugins under Vite 8 | Named verification item in the plan |
| SSR breaks a vendored `@lodekit/ui` component | SSR smoke test; fix offenders individually |
| Worker stream forwarding edge cases (abort, backpressure) | Timeout + error surface; e2e covers happy path, aborts covered by unit test |

## 13. Out of scope

Tasks (queue/schedule), secret-store's app door, integrations, inbound webhooks,
server-side `watch`, MCP redesign + skill rewrite (slice 3), local-door auth/hardening,
SPA mode, dashboard build freshness-skip, Windows/Linux.

## 14. Decisions log

| Authoring/RPC layer | TanStack Start wholesale (over Hono-routes+hc and standalone `'use server'` compiler — both PoC'd) |

| Rendering | Canonical SSR; no SPA mode |
| Isolation | Fault containment via per-app worker threads; no security sandbox |

| Webhooks | Explicitly blocked (soft same-origin guard on `/_serverFn/*`); future trigger slice |
| Dashboard | Start app #0 on the same substrate; dependency-free fallback page is the debug floor |
| Old contract | Hard cutover; examples migrated; SPA fallback + `index.html` rules deleted |
| Runtime internals | Stay Hono + hc (headless API unchanged) |
| Naming | **server function**, **app worker**; Stack/App-contract entries rewritten |
| Vite | 6 → 8 workspace-wide |
| Server bundle | Self-contained (`noExternal`); symlink fallback |
