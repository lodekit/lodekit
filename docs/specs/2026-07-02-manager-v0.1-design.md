# Lodekit Manager v0.1 — Design

**Date:** 2026-07-02
**Status:** Draft, pending review
**Role:** Slice-spec for slice 4 of the v0.1 derivation order (umbrella spec
`2026-07-02-product-overview-design.md`, §2.9 / §4). Specced ahead of slices 1–3; it builds
last, so everything it packages is whatever those slices ship. Where a detail depends on
them, this spec says so explicitly instead of guessing.
**Amends the umbrella:** §2.9's Node-provisioning wording and the package name — see §12.

## 1. Purpose

Turn the Electron dev shell into the canonical distribution: a packaged, installable macOS
menubar app that carries the platform, supervises the runtime, and is the one thing a
person downloads. v0.1 is the assisted alpha — we help each person install — so the design
optimizes for a failure-free first launch over download size or update mechanics.

### In scope

- Package rename: `@lodekit/desktop` → `@lodekit/manager` (folder `desktop/` → `manager/`).
- One artifact: `Lodekit.app` (macOS, arm64-only), ad-hoc signed, built by Electron Forge.
- Everything bundled: pinned Node + relocatable platform payload inside the .app (§3).
- Runtime lifecycle: spawn as a single direct child, health, crash surfacing, clean
  shutdown, stale-process cleanup, single-instance guard (§5).
- Menubar surface: status, Open Dashboard, Start/Stop, Start at Login, Open Logs, Quit (§6).
- The dev/default path-mode switch (§7).
- Stable in-bundle paths for the MCP server + skill, and the manual registration snippets (§8).

### Out of scope (deferred)

- **Developer ID signing + notarization** — alpha ships ad-hoc signed; testers right-click →
  Open. The pipeline keeps signing as a config toggle so Developer ID slots in without
  rework (later in 0.x, before any public download).
- **Windows/Linux**, universal (x64) macOS binaries.
- **Auto-update** and the managed-artifacts northstar (§2) — before 1.0, not now.
- **FTUX/onboarding** — automated MCP registration and skill linking (umbrella §2.9).
- **Auto-restart loops** — a crashed runtime surfaces as an error state with a Restart menu
  item; the manager never restarts it unprompted.

## 2. Provisioning principle & northstar

The constant across every version: **Lodekit manages its own dependencies, encapsulated,
never touching the person's system** — no system Node, no PATH edits, no global installs,
no conflicts with whatever the person already has. How the dependencies get on disk is an
implementation detail that evolves:

- **v0.1 (this slice): everything bundled, run in place.** The .app carries the pinned Node
  and the platform payload; first run provisions nothing but the Lodekit root. One
  download, works offline, one artifact, minimal failure modes — right for an assisted
  alpha.
- **Northstar (before 1.0): thin manager, managed artifacts.** The manager becomes a small
  supervisor that downloads, verifies, and manages *versioned* platform artifacts (Node +
  payload) under `~/Library/Application Support/Lodekit/` — enabling platform updates
  independent of the shell, side-by-side versions, and rollback. Bundling is step one on
  that path, not the destination.

## 3. Distribution artifact & payload

`Lodekit.app`, arm64, built by Forge `make` (distributed as a zip; a DMG maker is optional,
decided at plan time). Layout under
`Contents/Resources/`:

- **`node/`** — the pinned Node distribution. The version is pinned in exactly one place in
  the manager package (mechanism at plan time) and matches the version the repo is tested
  against. The runtime runs on this standalone Node, never Electron's embedded one —
  keeping `better-sqlite3` off Electron's ABI (existing rationale, unchanged).
- **`platform/`** — the relocatable payload, produced by a flattening/deploy step in the
  packaging pipeline (`pnpm deploy`-style; mechanics at plan time):
  - `runtime/` — `@lodekit/runtime` source + its production `node_modules` (`tsx`, Express,
    `better-sqlite3`, the Vite/React/Tailwind toolchain) including the workspace packages
    the toolchain resolves into apps (`@lodekit/sdk`, `@lodekit/ui`).
  - `mcp/` — `@lodekit/mcp` source + its production `node_modules`.
  - `skill/` — `@lodekit/skill` content.

Payload requirements (the contract, however the pipeline achieves it):

1. **Relocatable** — no symlinks escaping the bundle, no absolute paths baked in.
2. **ABI-matched** — native modules (today only `better-sqlite3`) are built for the pinned
   Node's ABI at package time, by construction (the pipeline runs on the same version).
3. **Read-only safe** — the runtime never writes inside the bundle; all writes go to the
   Lodekit root, the cache dir, and the log dir (§7).
4. **Contents track slices 1–3** — the payload bundles whatever the ui, kv-store v2, and
   mcp+skill slices ship; this spec fixes the layout, not their contents.

## 4. Package rename

The domain word is *manager* (`context.md`); the package keeps the implementation-detail
name `desktop`. This slice closes the gap: workspace member `desktop/` becomes `manager/`
(top-level, like `web/`), package `@lodekit/desktop` becomes `@lodekit/manager`.
`context.md`, the umbrella spec, and `CLAUDE.md` update to match (docs now, `CLAUDE.md`
when the code rename lands).

## 5. Lifecycle

The manager supervises one runtime child. States: `starting → running | stopped | error`.

- **Spawn:** `Resources/node/bin/node` directly on the runtime entry (via its `tsx`
  loader) — a single direct child; no shell, no pnpm, so kill semantics are exact. Env:
  `LODEKIT_ROOT`, `LODEKIT_CACHE_DIR`, `LODEKIT_PORT` (the runtime is already fully
  env-driven — `packages/runtime/src/config.ts`).
- **Health:** poll the runtime's HTTP surface until ready (as the dev shell does), then
  watch child exit. Ready → `running`.
- **First run:** create `~/Documents/Lodekit/apps` + `data` if absent, then open the
  dashboard in the browser once after the first successful start.
- **Crash:** child exits unexpectedly → `error`; menu shows the state and a Restart item.
  No automatic restart (failures surface, never crash — and never flap).
- **Quit:** SIGTERM, 5s grace, SIGKILL. Single direct child — no tree problem.
- **Stale runtime:** the manager writes the child PID to
  `~/Library/Application Support/Lodekit/runtime.pid`. On launch, if that PID is alive
  (manager previously crashed), terminate it before starting fresh.
- **Port conflict:** port 7777 occupied by something that isn't our PID-file child (e.g. a
  dev-mode runtime) → `error` with an explanatory status line; never kill what we didn't
  start.
- **Single instance:** `app.requestSingleInstanceLock()`; a second launch focuses nothing
  (there's no window) and exits.

## 6. Menubar surface

Tray-only: `LSUIElement` (no dock icon), no windows, no product UI — everything the manager
shows is the dashboard, in the browser (umbrella §2.9 contract).

Menu: status line (disabled item: "Lodekit — running / starting… / stopped / error: …"),
**Open Dashboard**, **Start/Stop** (contextual; **Restart** when `error`), separator,
**Start at Login** (checkbox → `app.setLoginItemSettings`, default off), **Open Logs**,
separator, **Quit**. Template menubar icon with an error variant; exact assets at plan
time.

Logs: runtime stdout/stderr → `~/Library/Logs/Lodekit/runtime.log`, manager events →
`manager.log`; rotated on manager launch (previous file kept as `.old`). "Open Logs"
reveals the folder.

## 7. Paths & modes

The dev/default path-mode switch (umbrella §4.1/§4.2), decided by `app.isPackaged`:

- **Default mode (packaged):** `LODEKIT_ROOT=~/Documents/Lodekit` (created on first run),
  `LODEKIT_CACHE_DIR=~/Library/Caches/Lodekit`, port 7777. The runtime's own defaults
  already point at `~/Documents/Lodekit`; the manager passes everything explicitly anyway
  so the contract is visible in one place.
- **Dev mode (run from the repo, `electron-forge start`):** current behavior — spawn via
  the workspace against `LODEKIT_ROOT=<repo>/examples`, system Node, default cache. The
  `LODEKIT_ROOT=./examples` stopgap stops being a stopgap and becomes the defined dev mode.

The runtime needs no changes for this slice — it is already env-driven; modes live
entirely in how the manager launches it.

## 8. MCP + skill exposure

The .app is also how the MCP server and skill reach the person's agent at v0.1 (manual,
assisted):

- **Stable paths are a contract:** `Resources/node/bin/node`, `Resources/platform/mcp/…`,
  `Resources/platform/skill/…` may not move between releases without updating the snippets.
- **Registration snippets** — per-agent MCP config (command = bundled Node, args = the MCP
  entry) and skill-linking instructions — live with the skill/readme (umbrella §2.9); their
  exact content depends on slice 3 and is written when this slice builds.
- The MCP server keeps reaching the runtime over HTTP only (invariant 4); nothing here
  changes that.

## 9. Packaging pipeline

Forge `package`/`make` extended with the payload step:

1. Flatten `@lodekit/runtime`, `@lodekit/mcp`, `@lodekit/skill` (+ workspace deps) into the
   relocatable payload (§3).
2. Fetch/stage the pinned Node distribution.
3. Both enter the .app as `extraResource`s; Forge produces the arm64 artifact, ad-hoc
   signed (Electron's default on Apple Silicon), with Developer ID as a dormant config
   toggle.

Known landmine, tracked from the monorepo migration: `desktop/.npmrc`'s
`node-linker=hoisted` only affects Forge's start check; before `make` works, the hoisting
question must be resolved at the workspace root — and every package re-verified under the
changed layout. This is plan-level work, but the spec flags it as part of this slice.

## 10. Error handling

- Runtime fails to become healthy within the startup budget → `error` state, log points at
  `runtime.log`. The manager stays up; the person can Restart or Quit.
- Runtime crashes while running → `error` (§5), no flapping.
- Port occupied → `error` with cause named (§5).
- First-run root creation fails (permissions, iCloud-synced Documents edge cases) →
  `error` with the path named in the status line and log.
- Manager crash → runtime keeps serving (person's apps stay up); next launch cleans up via
  the PID file.

## 11. Testing (minimum, per guardrails)

- **Lifecycle unit suite (vitest, new for this package):** the supervisor state machine
  extracted into a plain module with no Electron imports, tested against a fake child +
  stubbed health poll: start→running, crash→error, quit-kills-within-grace,
  stale-PID cleanup, port-conflict → error.
- **Packaged smoke checklist (scripted, manual):** on a clean macOS account with no system
  Node/pnpm — install, launch, menubar appears, root created, dashboard opens, an app
  builds and serves, MCP snippet registers with one real agent, quit leaves no orphan
  `node` process.
- No Electron e2e harness at v0.1.

## 12. Umbrella & docs amendments

Made alongside this spec (the umbrella requires amending before a slice departs from it):

- **Umbrella §2.9:** "always its own download" → bundled at v0.1 with the managed-download
  northstar (§2 here); package name → `@lodekit/manager`; §4.1 Manager row notes ad-hoc
  signing at v0.1 with Developer ID later in 0.x. Cohesion invariant 2 ("provisions its own
  pinned Lodekit-local Node — never the system's") holds unchanged under bundling.
- **`context.md`:** Manager entry package name → `@lodekit/manager`.
- **`roadmap.md`:** this slice absorbs "Electron packaging + Lodekit-local Node",
  "Electron shell + autostart", "Dev/default path-mode switch", and the macOS half of
  "Desktop spawn cross-platform + child-tree kill" (Windows spawn quirks stay parked); adds
  the managed-artifacts northstar and Developer ID signing as deferred entries.

## 13. Verification — what "done" proves

- `pnpm --filter @lodekit/manager make` produces an arm64 `Lodekit.app` on a dev machine.
- The packaged smoke checklist (§11) passes on a machine/account without system Node or
  pnpm — proving the platform is fully self-carried.
- Dev mode still works: `pnpm --filter @lodekit/manager start` runs against `examples/`.
- Quit and manager-crash scenarios leave no orphaned processes (checked via the checklist).

## 14. Open assumptions & dependencies

- **Builds last.** Payload contents, the skill's final form, and the MCP snippet all track
  slices 1–3; this spec freezes the layout and lifecycle, not their contents.
- **Node pinning mechanism** (where the version constant lives, how the distribution is
  fetched/cached at package time) is plan-level.
- **`better-sqlite3` stays the only native module**; if earlier slices add more, the
  ABI-by-construction rule (§3) covers them identically.
- **Apple Silicon only** is acceptable for the alpha's testers; revisit if an x64 tester
  appears.
