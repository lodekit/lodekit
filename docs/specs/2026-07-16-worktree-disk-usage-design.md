# Worktree disk-usage optimization

- **Date:** 2026-07-16
- **Status:** approved
- **Bead:** lk-p18 (brainstorming session)

## Problem

Development runs across long-lived git worktrees under `~/Code/worktrees/lodekit/`
(runtime, manager, infra, ui, service, web — all locked). The tree totals ~21G.
Measured breakdown:

| Category | Size | Detail |
|---|---|---|
| Manager build outputs | ~12.4G | `manager/{out,dist,build}` left behind by `pnpm --filter @lodekit/manager make` — 3.3G each in runtime/manager/infra, 1.4G in ui, 1.1G in service |
| node_modules | ~8.1G | 1.2–1.5G × 6 worktrees; verified **not** hardlinked across worktrees (distinct inodes). pnpm on APFS clones from the store, so physical blocks are partly shared with the 4.6G global store, but `du` sees the full logical size and sharing erodes across reinstalls |
| Everything else | <0.5G | `.git` dirs are 4K gitfile pointers (object store shared with the main clone — already optimal). `stack/`, `kv-store/`, `website/` are 8K leftover dirs, not registered worktrees |

The three manager directories are different pipeline stages:

- `build/` — input staging from `scripts/prepare-bundle.mjs` (`build/node` pinned
  Node download, `build/platform` pnpm-deployed payload); consumed by
  electron-builder via `extraResources`; regenerated by every `pnpm bundle`.
- `dist/` — electron-builder output (`directories.output: dist`): unpacked
  `mac-arm64/Lodekit.app` + distributable zip.
- `out/` — **dead**: the old Electron Forge output directory, unreferenced since the
  electron-builder migration. Once removed it never regenerates; it stays in the
  clean allowlist as belt-and-braces for older worktrees.

All three are disposable at any time (decision: confirmed in session — no packaged
apps are kept around).

## Decision

Two independent measures, both approved:

1. **Committed clean scripts** for build leftovers (durable) + a one-shot sweep now.
2. **pnpm global virtual store, machine-level** for node_modules duplication —
   user-level config, nothing committed, validated on one worktree before rollout.

Rejected alternatives:

- `git clean -fdX`-based cleaning — reuses `.gitignore` as the disposability source
  of truth but also deletes `node_modules`, `.env`s, and editor caches; too blunt.
- Automated cleanup (post-make hook, cron) — automation machinery for a one-liner;
  a `make` in one worktree can't clean siblings anyway.
- Repo-level `enableGlobalVirtualStore: true` in `pnpm-workspace.yaml` — ships an
  experimental flag to CI (where the docs note it has no benefit: no warm store)
  and to any collaborator. Machine-level keeps the blast radius to this machine.
- Do nothing about node_modules (rely on APFS clone sharing) — zero risk, but the
  sharing is invisible, unverifiable, and erodes; `du` keeps reading 21G.

## Design

### 1. Clean scripts (`pnpm clean`, `pnpm clean:worktrees`)

One dependency-free `scripts/clean.mjs` (plain Node — the repo is buildless), two
root `package.json` entries:

- `pnpm clean` — deletes the allowlist below in the **current** worktree.
- `pnpm clean:worktrees` — discovers all worktrees via
  `git worktree list --porcelain` and applies the same allowlist to each.

Canonical disposable allowlist (fixed, relative to a worktree root):

```
manager/out          # dead Forge output
manager/dist         # electron-builder output
manager/build        # prepare-bundle staging
web/main/dist        # Astro build output
web/main/.astro
web/docs/dist
web/docs/.astro
```

Explicitly kept: `node_modules` anywhere (cleaning must never force a reinstall)
and `manager/.node-cache` (49M download cache that saves re-fetching the pinned
Node on the next `make`).

Safety properties:

- The script deletes **only** the fixed allowlist joined to worktree roots taken
  from `git worktree list --porcelain` — no globs, no user-supplied paths, no
  `.gitignore`-derived deletion.
- It reports each path deleted and bytes reclaimed per worktree; missing paths are
  silently fine.

One-shot: run `pnpm clean:worktrees` once the script lands (expected reclaim
~12.4G) and manually remove the three stub dirs (`stack/`, `kv-store/`,
`website/`).

### 2. Global virtual store (machine-level)

Enable in the user-level pnpm config (nothing committed):

```
pnpm config set enable-global-virtual-store true
```

Requires pnpm ≥ 10.12.1 (machine has 10.30.3; setting is experimental). Each
worktree's `node_modules/.pnpm` becomes symlinks into one shared virtual store
under pnpm's data dir, collapsing ~8.1G of per-worktree duplication to roughly one
copy and making fresh-worktree installs much faster.

**Validated rollout** — one worktree (runtime) first:

1. Remove `node_modules` (root + packages), `pnpm install`.
2. Verify the layout changed: `node_modules/.pnpm` entries are symlinks resolving
   outside the repo.
3. Run the real checks: `pnpm test` (runtime, sdk, ui, manager, integration —
   includes `better-sqlite3` native loading) and a `pnpm dev` boot smoke-check.
4. Only if green: reinstall the remaining five worktrees the same way, then
   `pnpm store prune`.

**Known risk:** the documented ESM caveat — pnpm's hidden-hoisting fallback does
not work through a global virtual store, so a dependency importing a package it
doesn't declare fails at import time. This surfaces immediately in step 3.
Mitigation ladder: `packageExtensions` entry in `pnpm-workspace.yaml` for the
offending package; if messy, full rollback via
`pnpm config delete enable-global-virtual-store` + reinstall. Nothing is destroyed
by trying.

**Failure stance:** if validation fails and the fix isn't a quick
`packageExtensions` entry, roll back, file a `defer` bead with findings, and keep
measure 1 (which alone reclaims most of the space).

## Expected end state

~21G → roughly 3–4G across worktrees (sources + symlinks + rebuilt native
modules), with one shared virtual store and the 4.6G content-addressable store on
the machine. Verified with before/after `du -sh` on
`~/Code/worktrees/lodekit`.

## Testing

- `scripts/clean.mjs`: exercised by running `pnpm clean` in a worktree with known
  leftovers and asserting the allowlist paths are gone while `node_modules` and
  `manager/.node-cache` survive; `pnpm clean:worktrees` verified against
  `git worktree list` output.
- Global virtual store: `pnpm test` + `pnpm dev` boot in the runtime worktree
  before any further rollout (step 3 above is the gate).

## Out of scope

- CI/collaborator adoption of the global virtual store (revisit if/when the flag
  stabilizes).
- Automated/scheduled cleaning.
- Changelog entry — internal tooling, not user-facing.
